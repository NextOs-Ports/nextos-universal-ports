# Forager Nuclear — Android 1.0.13 compatibility port

**Language / Idioma:** [English](#english) · [Português](#português)

This repository contains only the free compatibility loader and PortMaster
integration. It does not contain Forager, an APK, game assets, music or saves.

## English

### Status

Playable ARMv7/armhf port of the Android GameMaker build. The validated path has
working GLES2 video, music and sound effects, controller input, saves, clean
Select+Start exit and all twelve language files shipped by the game. It was
physically validated on the NextOS Mali-450/GLES2 baseline and an ARMv7-capable
ArkOS family device.

### Architecture

The visible `Forager.sh` launcher is generated by nxbootstrap 0.6.8. It owns the
PortMaster handoff, one-instance lock, NXExtract invocation, required-file gate,
signal supervision and finalization. The port then follows the native GameMaker
flow:

1. NXExtract 1.2.6 selects the owner's Android package and creates a deterministic
   STORE-only `runtime/forager.port`.
2. `forager-nextos` loads the original ARMv7 `libc++_shared.so` and `libyoyo.so`,
   resolves their Android imports and runs the original initializers.
3. The fake Android/JNI layer supplies the GameMaker runner services and preserves
   the game's original startup and main loop.
4. SDL2 provides the real GLES2 window, audio output and GameController input.
5. Writable configuration and saves remain in `data/`, outside the NXExtract
   payload seal.

### Solved problems

| Problem | Cause | Port-local fix |
|---|---|---|
| Android runtime stopped during startup | incomplete Bionic/libm surface and ARM softfp ↔ hard-float calls | generated libc thunks plus explicit math, zlib and runtime imports |
| HUD script received `undefined` | missing Java classes and incorrectly typed extension returns | typed fake-JNI objects and inert, success-shaped extension callbacks |
| Background music was effectively inaudible | Android defaults encoded strong attenuation | install the physically approved volume config only on a clean data directory |
| Saved English returned after selecting another language | the game called its own `SelectLanguage` after Android locale detection | exact GameMaker `SelectLanguage` boundary hook delegates to the original function with the selected native asset |
| Some ARMHF systems could cross EGL/GLES providers | versioned and unversioned links resolved to different objects | capability-gated coherent provider pair, only when the mismatch is proven |
| Controller could appear to lose most buttons | incomplete GameMaker button mask / test process interference | full native SDL button mask, stable hotplug tracking and no runtime test killer |
| Normal destructor path crashed after exit | guest audio/GL threads remained alive during teardown | Select+Start requests terminal exit after in-game persistence, without unsafe guest destruction |

All fixes above are confined to this adapter. No game-specific offset or behavior
is enabled globally in the framework.

### Controls

- Left stick or D-pad: move and navigate
- A/B/X/Y: native game actions and menu confirm/cancel
- Shoulders and triggers: native secondary actions
- Start: pause/menu
- Select+Start: exit the port

PortMaster/firmware SDL mappings keep priority. The package adds exact fallback
mappings only for controller identities physically observed during this port.

### Languages

With `GAME_LANGUAGE="auto"`, the launcher opens the PortMaster language list and
stores the choice in `data/language.txt`. Supported choices are Brazilian
Portuguese, English, Spanish, French, German, Russian, Turkish, Thai, Japanese,
Korean, Simplified Chinese and Traditional Chinese. The last selection survives
process restarts and never invalidates the extracted runtime.

### Owner game data

Put a lawful Android 1.0.13 package you own in `forager/gamedata/` and launch the
game. The filename does not matter. NXExtract can discover a loose APK or the base
APK inside APKM/APKS/XAPK containers. Re-signing, ZIP metadata, compression and
unrelated store files may differ; every one of the 24 members consumed by this
runner is checked by exact size and SHA-256 before publication.

The package is never deleted. The generated runtime is transactionally committed,
and later launches use the fast marker. APKs, extracted runtime data and saves must
never be committed to this source repository or attached to a release.

### Build

```bash
cd source
./build-release.sh ../forager-nextos
```

The release recipe pins gmloader-next commit
`c2fca354df73761887c15f44a0b28ec823581cd5` and a Debian Buster image by digest.
The resulting ARM EABI5 hard-float executable has no RPATH/RUNPATH and requires at
most GLIBC 2.28.

### Source map

- `source/overlay/gmloader/libyoyo.cpp` — GameMaker load and native language boundary.
- `source/overlay/gmloader/classes/RunnerJNILib.cpp` — typed Android extension bridge.
- `source/overlay/gmloader/input.cpp` — GameController, hotplug, rumble and exit chord.
- `source/overlay/jni/` — fake-JNI classes used by the original runner.
- `source/overlay/loader/so_util.cpp` — ARMv7 Android ELF loading and relocation.
- `source/overlay/thunks/` — Bionic, GLES2, OpenAL and zlib compatibility calls.
- `tools/build_forager_port.py` — deterministic and content-pinned owner-package transform.
- `extractor.json` — NXExtract input, transaction and payload-seal contract.
- `adapter/adapter-contract.json` — lifecycle, persistence and physical validation boundary.

## Português

### Estado

Port ARMv7/armhf jogável da versão Android/GameMaker. O caminho validado tem vídeo
GLES2, música e efeitos, controle, saves, saída limpa com Select+Start e os doze
idiomas fornecidos pelo jogo. Foi comprovado fisicamente no baseline NextOS
Mali-450/GLES2 e em um aparelho da família ArkOS com suporte ARMv7.

### Arquitetura

O launcher visível `Forager.sh` é gerado pelo nxbootstrap 0.6.8 e cuida da entrega
PortMaster, lock de instância única, NXExtract, arquivos obrigatórios, sinais e
finalização. Depois o port preserva o fluxo nativo do GameMaker:

1. O NXExtract 1.2.6 escolhe o pacote Android do dono e cria o arquivo determinístico
   `runtime/forager.port` sem compressão.
2. `forager-nextos` carrega `libc++_shared.so` e `libyoyo.so` ARMv7 originais,
   resolve imports Android e executa seus inicializadores.
3. A camada Android/JNI fornece os serviços do runner sem pular o startup ou o loop
   original do jogo.
4. O SDL2 fornece janela GLES2, áudio e GameController reais.
5. Configurações e saves graváveis ficam em `data/`, fora do selo do NXExtract.

### Problemas resolvidos

- Superfície Bionic/libm completa com ponte correta softfp ↔ hard-float.
- Objetos JNI tipados e callbacks de extensões Android inertes, mas com retorno válido.
- Volume inicial de música corrigido somente na primeira instalação, preservando as
  alterações posteriores do jogador.
- Escolha de idioma aplicada no `SelectLanguage` nativo do jogo e persistida entre
  processos.
- Par EGL/GLES coerente apenas quando o conflito de providers é realmente provado.
- Máscara completa de botões, hotplug estável e nenhum processo de teste matando o pad.
- Saída Select+Start sem desmontar threads guest de áudio/GL ainda ativas.

Essas correções pertencem somente ao adapter do Forager; nenhuma delas vira default
global por nome de firmware ou jogo.

### Controles

- Analógico esquerdo ou D-pad: mover/navegar
- A/B/X/Y: ações nativas e confirmar/cancelar nos menus
- Ombros e gatilhos: ações secundárias nativas
- Start: pausa/menu
- Select+Start: sair do port

Os mappings SDL do PortMaster/firmware têm prioridade. O pacote só acrescenta
fallbacks exatos para controles observados fisicamente neste port.

### Idiomas

Com `GAME_LANGUAGE="auto"`, o launcher mostra a lista do PortMaster e grava a escolha
em `data/language.txt`. Há Português do Brasil, Inglês, Espanhol, Francês, Alemão,
Russo, Turco, Tailandês, Japonês, Coreano, Chinês Simplificado e Chinês Tradicional.
A escolha sobrevive ao reinício do processo e não invalida o runtime extraído.

### Dados do dono

Coloque em `forager/gamedata/` um pacote Android 1.0.13 adquirido legalmente e abra
o jogo. O nome não importa. O NXExtract encontra APK solto ou o APK base dentro de
APKM/APKS/XAPK. Assinatura, metadados ZIP, compressão e arquivos extras da loja podem
mudar; os 24 membros efetivamente usados são validados por tamanho e SHA-256 exatos.

O pacote nunca é apagado. O runtime é publicado por transação e as próximas aberturas
usam o marcador rápido. APK, runtime extraído e saves nunca entram no repositório nem
na release.
